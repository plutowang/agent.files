# Prompt Authoring Guide — Best Practices for agent.files

**Date:** 2026-08-15 · **Audience:** any agent (or human) creating, modifying, or auditing prompts, skills, rules, agents, or commands in this repository. Mandatory companion to the `agent-architect` skill.
**Origin:** distilled from the 2026-08-12 refactoring session and the 2026-08-15 wording-optimization session (research-backed: see §8).

---

## 1. Architecture recap — where things go

- **`_core/` = single source of truth.** Concept folders: `1_governance/` (laws), `2_workflows/` (processes), `3_engineering/` (standards), `4_refactoring/`, `5_commands/`, `skills/`. Each concept holds only the fragment types it needs: `redlines.md`, `protocol.md`, `standards.md`, `memory.md`, `preflight.md`.
- **Shells (`opencode/`, `cursor/`) = thin import containers**: frontmatter + XML skeleton + `<!-- @import path -->` lines + minimal IDE glue (names, `$ARGUMENTS`, interlocks). No rule content lives here except IDE-specific mechanics.
- **`dist/` = compiled output.** Never edited; regenerated by `./agentc-cli build`; deployed via `./agentc-cli link <ide>`.
- **Imports** are repo-root-relative, inlined at directive position, and recursive. When changing a rule, edit its ROOT fragment — trace import chains first.

## 2. Fragment format spec (canonical — enforce on every edit)

| Fragment | Format |
|---|---|
| `redlines.md` | Plain `- ` bullets. Bold labels ONLY for grouping. NO tables, NO numbered lists, NO bold-prefixed items. (Exception: the two TDD Iron Law lines keep bold.) |
| `protocol.md` | Bold labels for subsections; numbered steps for sequences; bullets for non-sequential. |
| `standards.md` / `memory.md` | Bold labels + bullets + tables (reference data). |
| `preflight.md` | `- [ ]` checkboxes. |

- Fragments may import only **same-section-type** fragments (redlines→redlines, etc.).
- **Whitespace compaction**: no blank-line padding between a label and its bullets, or between bullets — blank lines inflate `wc -l` by ~30% and cost tokens for zero information. Keep ONE blank between fragments inside a shell.

## 3. Hard rules (non-negotiable)

1. **Lexical Ban (`_core/` only):** no `glob`, `grep`, `Task` tool, `build` subagent, `YAML frontmatter`, `@Codebase`, `.mdc`. Write goal-oriented ("Search the codebase") not tool-oriented ("Use glob").
2. **IDE-neutrality:** `_core/` uses ROLE names only ("the security review agent"). Shells supply IDE names (opencode `security-reviewer`, cursor `/security-auditor`).
3. **`edit_accuracy/memory.md` importable ONLY by write-enabled agents** (build, refactor, docs, build-error-resolver). Never in read-only agents or global files.
4. **Permission alignment:** prompt text must match the shell's YAML block. If a shell denies a tool, never instruct using it.
5. **Cursor `.mdc` hygiene:** `alwaysApply: false` + specific globs (except true project-wide safety); `/`-syntax interlocks (NOT `@`); no OpenCode mechanics. Subagent role constraints belong in agent files ONLY — never leak "read-only / no searches" into `.mdc` rules (that forbids the primary agent).
6. **Frontmatter byte-identical** except density-rewritten descriptions: trigger-accurate, third person, what+when, ≤1024 chars.
7. **`dist/` never edited** — always verify via rebuild + read-back.
8. **HITL:** plan approval before multi-file changes; per-phase gates; no commits unless instructed.

## 4. Density & budget rules (2026-08-15, research-backed)

- **Line budgets (total file lines incl. frontmatter):** agents/commands **≤ 200**; skills **≤ 500**; `.mdc` rules **≤ 500**. AGENTS.md/global ≤ 200.
- **Rule-count budget:** ~40 rules per compiled prompt max (compliance collapses as rule count grows — failure begins in single digits for weak models).
- **State each rule once.** Import, never restate. Delete exact duplicates (record the surviving location). Contradictions must be resolved AT AUTHORING TIME — models resolve them silently and arbitrarily; placement is not precedence.
- **Zero-loss discipline:** wording may change; no constraint is ever dropped. Every change gets an audit matrix: constraint count IN == OUT (additions get their own cited row).
- **Conciseness = accuracy, not deletion:** more accurate with fewer words; trim introductions, repetition, filler — never required facts or references. Pair "be concise" with content-preservation clauses.
- **MUST/NEVER only for true invariants** (safety, gates, laws). Repeated "ask first / wait for approval" rules cause over-asking — state once, anchor-reference (`⏸ (I)`) elsewhere.
- **Negative constraints re-anchored at the end** (preflight) — models drop early negatives; positives/goals early, NEVER-style rules re-stated at the end.

## 5. Workflow: adding a new rule or prompt

1. **Locate the concept folder** (existing, or new `N_category/concept/`). A rule about testing goes in `3_engineering/testing_*`, never in a shell.
2. **Pick the fragment type by nature:** invariant → `redlines`; sequence/process → `protocol`; reference/thresholds → `standards`; context/reporting → `memory`; completion gate → `preflight`.
3. **Write it** — format spec (§2) + Lexical Ban + density rules (§4). List the constraints it adds.
4. **Audit matrix** — count constraints IN; after wiring, count OUT; they must match.
5. **Wire imports** in BOTH shells (opencode + cursor) inside the matching XML section. Respect permission alignment + edit_accuracy isolation. Role-specific lines go in the shell, not the shared fragment.
6. **Verify:** `zig build test` (EXIT 0) → `./agentc-cli build` (SUCCESS) → dist read-back (one of each XML tag per shell, no fragment headings, no within-file duplication, no internal path refs) → `wc -l` budget check.
7. **HITL:** present per-phase; wait for approval.
8. **Sync** `docs/context/` + `docs/plans/` with what changed.

## 6. Creating a new skill

- Path: `_core/skills/<name>/SKILL.md` (compiler ships verbatim to `dist/cursor/skills/`).
- **Standalone** — skills keep their own pyramid (`<red_lines>`, `<execution_protocol>`, `<standards>`, `<pre_flight_check>`); they are not imported into shells.
- Frontmatter: `name`, `description` (trigger + when, third person, ≤1024 chars), optional `license`.
- ≤ 500 lines; canonical format spec; Lexical Ban applies.
- Research-heavy skills cite sources with URLs; every claim needs one.

## 7. Creating a new agent, command, or IDE shell

- **Agent (opencode):** frontmatter = description/mode/temperature/steps/color/permission (read, glob, grep, edit, skill, bash, task blocks). Grant read only where the agent's output depends on file contents; grant search only where diagnosis requires it. Prompt body = intro line + XML skeleton + imports.
- **Agent (cursor):** frontmatter = name/description/model/readonly/is_background. `model: fast` for high-volume (verifier, debugger); `model: inherit` for deep reasoning (architect, security). Context-isolated — prompt must say how to gather context.
- **Command:** frontmatter = description; body = `$ARGUMENTS`/`$1` glue + imports.
- **New IDE:** create the target dir, map its required layout, write minimalist shells (frontmatter + imports only), add the target to `agentc/core/config.zig` `targets`, rebuild the binary, test, then link.

## 8. Research foundations (why these rules exist)

| Rule | Evidence |
|---|---|
| ≤200-line prompts; dedup; state once | OpenAI GPT-5.x: leaner prompts +10–15% scores, −41–66% tokens; "state each rule once"; Claude Code: <200 lines per CLAUDE.md, contradictions → arbitrary pick |
| Contradictions are the worst defect | "conflicting rules can create more instability than missing detail"; models resolve them silently (97.5%); precedence does not follow prompt depth |
| Rule-count ~40 | arXiv:2608.12426 (compliance <50% at 7 constraints for strong models); arXiv:2607.19257 (collapse by ~80 rules) |
| MUST/NEVER moderation | OpenAI: absolutes only for true invariants; repeated approval rules cause over-asking; Anthropic Opus 4.8: literalism — state scope explicitly |
| Negative constraints at end | Gemini 3 prompting guide; MiniMax: task at end (largest single impact), boundaries before task |
| Flat structure, no deep nesting | MiniMax prompting best practices: "deep nesting hurts readability" |
| Whitespace compaction safe | arXiv:2503.19114 — compressing semantics kills grounding; whitespace is free |
| Zero-loss matrices | CDCT (2512.17920): "state fully or cut decisively" — medium-length truncation is worst |

## 9. Verification battery (run after EVERY change batch)

```bash
zig build test        # EXIT 0
./agentc-cli build    # SUCCESS, 104 files
wc -l dist/...        # budgets: agents/commands ≤200, skills ≤500, .mdc ≤500
# dist read-back: one of each XML tag per shell; no fragment headings;
# no within-file duplication; no internal path refs (source-repo agents excepted)
```

**Remember:** this repo compiles prompts. Edit the source of truth, never the output; state rules once; verify by rebuild; and treat every constraint as load-bearing until its removal is explicitly approved.
