## 1. The Architectural Foundation (The `agent.files` Paradigm)

This project uses a custom Zig compiler (`agentc`) to generate system prompts and commands for multiple AI IDEs from a Single Source of Truth (`_core/`).

### A. The Universal Source (`_core/`)
- **Purpose**: Abstract software engineering philosophies, shared skills, and shared command logic.
- **THE LEXICAL BAN**: Files in `_core/1_governance/` through `_core/4_refactoring/` MUST NEVER contain IDE-specific mechanics (e.g., `glob`, `grep`, `Task` tool, `explore` subagent, `YAML frontmatter`, `@Codebase`). Write abstractly.
- **Dimensional Structure**:
  - `1_governance/`: Supreme laws (HITL, anti-loop, safety).
  - `2_workflows/`: Process flows (git ops, feature dev, triage).
  - `3_engineering/`: Quality standards (architecture, testing, security).
  - `4_refactoring/`: Tech debt management.
  - `5_commands/`: Core logic for slash commands.
  - `skills/`: Atomic capabilities (e.g., `go`, `aws`).

### B. The Host Shells (The Target IDE Directories)
- **Purpose**: The physical bodies. They contain the YAML frontmatter, tool permissions, and explicit routing mechanics unique to that IDE.
- **Macro Injection**: These files assemble the final prompt by calling `<!-- @import _core/... -->` at their bottom.

### C. The Compiled Output (`dist/`)
- **NEVER edit files in `dist/`.** They are ephemeral, generated by `agentc`.
